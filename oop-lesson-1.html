How this lesson works

Paper 4 is sat at a computer. You cannot learn it by reading about it, so this page teaches, then makes you type.

  1. Learn on this page. Predict what code will do, run it here in the browser, then pick it apart. Nothing to install.
  2. Build it in Python on your own machine. The page's runner is for experimenting. Your assessed code is written in IDLE, Thonny or VS Code, exactly as it will be in the exam.
  3. Evidence it. Paste your code as text and your screenshots into the Evidence Document, and submit it on Teams. That document is a copy of the one Cambridge makes you fill in on exam day, so you are practising the exam admin as well as the code.

Why the evidence document matters

Examiners report marks lost in every single series for evidence, not for code: screenshots that show the output but not the inputs, code pasted as a picture instead of text, missing tests, Python indentation destroyed. Those are free marks and you are going to get into the habit of taking them now.

Where this sits in the paper

A class appears in every one of the last 29 Paper 4 examiner reports. It is not an optional topic — it is roughly a third of the paper, every year. Examiners now say that declaring classes has become a national strength, and that the marks are being lost further on, at the point where candidates have to create objects and use them. We start at the declaration this week and spend the next five on the part that is actually costing marks.

Vocabulary

Key terms — learn these wordings

These are written the way a mark scheme writes them. A looser paraphrase of the right idea scores nothing, so learn the wording, not the gist.

TermDefinition that earns the mark
ClassA template (blueprint) that defines the attributes and methods of a type of object.
ObjectAn instance of a class.
Attribute
(property)		A data item belonging to an object, declared with a data type.
MethodA subroutine belonging to a class that defines a behaviour of its objects.
ConstructorThe method that runs automatically when an object is created, which initialises the object's attributes.
InstantiationThe process of creating an object from a class.
EncapsulationAttributes are declared private so they can only be accessed through the class's own methods.

What examiners reject

"A class is an object" — no mark. "An object is a copy of a class" — no mark; it is an instance. "Encapsulation means hiding the code" — no mark; it is about the data being private and reached only through methods.

Try this — then read why it matters

Add this line to the bottom of the code above and run it again:

print(MyBook.__Title)

It crashes with an AttributeError. That crash is encapsulation working. The double underscore has made __Title private, so code outside the class cannot touch it directly. To read it, the class has to offer you a method — which is exactly what next week's lesson builds.

PRIMM · Step 3

Investigate — the four parts of a class

1. The class header

class Book: — the name is a singular noun with a capital letter. Book, not Books, and not BookClass. The class describes one of the thing; you make as many objects from it as you like.

2. Private attributes, with their data types visible

Python has no PRIVATE keyword and no type declarations, so you have to show the examiner what a VB.NET or Java candidate gets for free:

You writeWhat it evidences
self.__TitleThe two leading underscores make the attribute private. One underscore is not enough.
# STRINGA comment naming the data type. Examiners accept a comment as evidence of the data type — and without it you are relying on the marker's goodwill.

Write both, every time, on every attribute. It costs you four seconds and it is a mark.

3. The constructor

In Python the constructor is always called __init__ — two underscores, init, two underscores. Its first parameter is always self.

The misspelling that costs the whole question

Examiners name __int__ as a recurring error. Python does not complain — it simply never runs your constructor, so every attribute is missing and every method that follows crashes. If your object "has no attribute", check the spelling of __init__ first.

4. A method

Display() is a method: a subroutine that belongs to the class. Its first parameter is self, and it is called on an object with a dot — MyBook.Display().

Checkpoint 1

Which line correctly declares a private attribute and evidences its data type, in a Python class?

This attribute is public — any code anywhere can change it, so there is no encapsulation to credit, and nothing shows the data type. This is the commonest version of the error.
One underscore is a convention meaning “please don't”; it does not make the attribute private, and Python will happily let outside code read it. Use two.
Two underscores make it private, and the comment evidences the data type. This is the form to use on every attribute, every time.
That is a get method, not an attribute declaration. It is a real thing you will write next lesson, but it does not declare or store anything.

Read the right-hand column very carefully

OnLoan and TimesBorrowed say "always". That means the constructor assigns them itself — they are not parameters. A constructor that takes five parameters when the design specifies three has not followed the design, and examiners mark it as wrong even when the code runs perfectly. Count the parameters against the design before you write the header.

Model answer — check yours against this
Python — Paper 4 
class Book:
    def __init__(self, Title, Author, Year):
        self.__Title = Title             # STRING
        self.__Author = Author           # STRING
        self.__Year = Year               # INTEGER
        self.__OnLoan = False            # BOOLEAN
        self.__TimesBorrowed = 0         # INTEGER

    def Display(self):
        print("Title          : " + self.__Title)
        print("Author         : " + self.__Author)
        print("Year           : " + str(self.__Year))
        print("On loan        : " + str(self.__OnLoan))
        print("Times borrowed : " + str(self.__TimesBorrowed))

FirstBook = Book("Dune", "Frank Herbert", 1965)
SecondBook = Book("Emma", "Jane Austen", 1815)
FirstBook.Display()
SecondBook.Display()

Three parameters, five attributes. Two objects from one class — that is the whole point of a class.

Checkpoint 2

A class Member has a constructor. Which line creates an object of that class correctly?

Naming the variable after its class is an error examiners name in four separate series. You have just overwritten the class with an object, so the very next Member(...) in your program crashes.
The variable is named after what the object is, not after its class, and the constructor's arguments are passed in the order the design gives them.
This calls the class as though it were a plain procedure and stores nothing. Calling methods as free procedures instead of on an object appears in six of the last ten series — it is one of the two habitual instantiation errors.
new is Java and C#, not Python. Every language on this paper has its own instantiation syntax and you must use the one for the language you are sitting.

The marks

Exam technique — the class design table is the instruction

Almost everything that goes wrong on an OOP question goes wrong before any code is written, because the candidate implemented the class they remembered rather than the class they were given. Cambridge does this deliberately: the designs change slightly every year specifically to test whether you read them.

Predict, then reveal. A candidate is given the Book design above and writes this. Decide what an examiner would say before you open the answer.

Candidate response 
class Book:
    def __init__(self, Title, Author, Year, OnLoan, TimesBorrowed):
        self.Title = Title
        self.Author = Author
        self.Year = Year
        self.OnLoan = OnLoan
        self.TimesBorrowed = TimesBorrowed
What the examiner says

The code runs. It still loses most of the available marks.

  • ✗ Attributes are public. No double underscores, so there is no encapsulation to credit.
  • ✗ No data types evidenced. No comments, so nothing shows what type each attribute is meant to hold.
  • ✗ Wrong parameters. The design says OnLoan and TimesBorrowed are always set to fixed values. Taking them as parameters means the class does not meet the specification, and it lets the caller create a book that has already been borrowed 400 times.
  • ✓ The constructor is correctly named and the three genuine parameters are assigned the right way round.

The habit to build: before you write the class header, put a finger on the design table and count how many attributes come from a parameter. That number is how many parameters your constructor takes, after self. Everything else is assigned inside.

Checkpoint 3

A class design states: "Attribute Balance, INTEGER, set to 100 when the object is created." Which constructor follows the design?

This takes Balance as a parameter. The design says it is set to a fixed value on creation, so it must not be a parameter.
The fixed default is assigned inside the constructor, and the data type is evidenced by a comment.
"100" in quotes is a string, not an integer. Examiners have sharpened up on exactly this since 2025: -1 and '-1' are not the same thing, and neither are these.
The assignment is the wrong way round — this copies the empty attribute into the parameter and leaves the attribute undefined. It is the classic setter error, and it appears in constructors too.

Before you screenshot

  • Use exactly the test data given. Inventing your own loses the mark even if the program is perfect.
  • The screenshot must show the inputs as well as the outputs. This is the single most repeated technique failure in the examiner reports — present in all ten recent series.

  • Your code goes into the document as text, never as a screenshot. Screenshotted code scores nothing.

Accepted alternatives

  • The data type may be evidenced by a comment, by a type hint, or by an obviously typed initial value — any of the three earns MP4.
  • DisplayDetails() may build one long string and print it once, or print line by line. Both are accepted.
  • Labels may be worded however you like, as long as each attribute is identifiable.

Not credited, however good the code looks

  • Public attributes — MP3 lost, and MP4 usually with it.
  • Credits or Active taken as parameters — MP2, MP6 and MP7 lost. Three marks for not reading the table.
  • DisplayDetails() that returns a string instead of outputting it — MP8 lost. The design says "outputs".
  • A screenshot with the output but not the test data — MP11 lost.
  • Code pasted as an image — no code marks at all.
