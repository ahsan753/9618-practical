The trap this lesson is about

In five examiner reports since November 2022, across four exam series, Cambridge has named candidates using inheritance where the design called for containment — the equivalent of writing class Club(Member): when a club has an array of members. The code often runs. It still loses the class-declaration marks, and usually the constructor marks with them, because the candidate built the wrong relationship. The whole decision takes ten seconds once you know where to look in the design table — and that is what you are about to learn.

Vocabulary

Key terms — learn these wordings

TermDefinition that earns the mark
Containment
(aggregation)		A relationship where one class has an attribute (property) that is an object, or an array of objects, of another class. The container has the other objects.
InheritanceA relationship where a child class derives the attributes (properties) and methods of a parent class, and can add its own or override them. The child is a kind of the parent.
Parent class
(superclass, base class)		The class whose attributes and methods are inherited.
Child class
(subclass, derived class)		The class that inherits from a parent class.

How definitions lose the mark

Don't define a word with itself. Examiners reported (Nov 2022) that "a new class inherits the attributes and methods from a parent class" was not enough to define inheritance — they wanted it to derive them. Cambridge's standing instruction: use the words property, method, class and object when you define an OOP term.

"Containment is when a class is inside another class" is risky — it sounds as if one class is declared inside the other, which is not what happens. Say that one class has an attribute whose value is an object, or an array of objects, of the other class.

PRIMM · Step 3

Investigate — has a, or is a?

1. The one-question test

Say the two class names in a sentence. If "A ___ is a ___" is true, it is inheritance. If "A ___ has ___" is true, it is containment. Only one of them will sound right.

SentenceTrue?Relationship
A shelf is a book.✗ NoContainment — Shelf has an array of Book
A shelf has books.✓ Yes
A novel is a book.✓ YesInheritance — Novel is a child of Book
A club has members.✓ YesContainment
A savings account is an account.✓ YesInheritance

2. Where the design table tells you

In the exam you do not have to guess from the names. The design says which it is — you just have to look in the right place.

Containment — look for…Inheritance — look for…
Another class's name in the data type column of an attribute:
Books : ARRAY[0:2] OF Book
Captain : Member		Words in the description such as "is a subclass of", "inherits from", "child class of" — or a class diagram with an arrow from the child to the parent.

The rule to apply: if the other class appears as an attribute, it is containment — no brackets after the class name and no super().

Checkpoint 1

A class design reads: Class Garage. Attributes: GarageName : STRING; Vehicles : ARRAY[0:9] OF Car. Which class header follows the design?

This makes Garage a child of Car — it says a garage is a car. Car appears in the data type column of an attribute, so a garage has cars. This is exactly the error examiners have reported five times since 2022.
Vehicles is the name of an attribute, not a class. Python stops with a NameError. The brackets after a class name are only ever for a parent class.
Car appears in the data type column, so this is containment: the garage has an array of cars. The class needs no parent, so there are no brackets — the array is declared inside the constructor.
This makes every car a kind of garage. Nothing in the design says that, and it gets the direction of the relationship backwards as well.

3. What containment looks like in Python

class Shelf:                            # 1. no parent class in brackets
    def __init__(self, Label):
        self.__Label = Label            # STRING
        self.__Books = [None] * 3       # 2. ARRAY[0:2] OF Book, private
        self.__Count = 0                # 3. INTEGER — how many are stored
  1. No parent class. class Shelf: — nothing in brackets, and so no super().__init__ anywhere.
  2. The contained objects live in a private attribute, created in the constructor, with its type shown in a comment exactly as you did for STRING and INTEGER. It is not a constructor parameter unless the design says so.
  3. A counter records how many objects are actually stored, so that methods can loop over those and no further.

Read what "empty" means in the design

This design says the elements start empty, so [None] * 3 with a type comment is right — examiners describe stronger Python candidates as having "used a comment to indicate the data type intended" (Nov 2021). But some designs say the array is initialised with objects — for example twenty nodes each holding -1. Then an object must be created and stored in every element; None will not earn the mark (Jun 2024). The design decides, not habit.

4. Work through their methods, not their attributes

Inside Shelf, a book's title is still private to Book. The shelf has to ask for it, exactly as the main program did last week.

Inside a Shelf method you writeWhat happens
self.__Books[Index].GetPages()✓ The book returns its pages.
self.__Books[Index].__Pages✗ AttributeError: 'Book' object has no attribute '_Shelf__Pages'. Private means private to the class that declared it. Shelf is a different class.
self.__Books.GetPages(Index)✗ Crash — the array is a list, and a list has no GetPages. Pick the element first.

Pass the object, not its data

The design says AddBook(NewBook) — one parameter, and it is a Book. So the caller creates the object and hands it over: Fiction.AddBook(Book("Dune", 412)). Writing AddBook(self, Title, Pages) and building the book inside does not follow the design. Examiners have reported exactly this — passing the integer and string values instead of the object — in Nov 2022 and again in Jun 2024.

Checkpoint 2

Inside a method of the class Team, the attribute self.__Players holds Player objects, and each Player has a get method GetGoals(). Which line, inside for Index in range(0, self.__Count):, adds one player's goals to Total?

Array, then element, then the element's own method — and the value it returns is added to the total. The Team works through the player, never around it.
__Goals is private to Player. Inside Team, Python renames it to _Team__Goals, which does not exist, so this crashes with an AttributeError. Call the get method.
This calls the method on the whole list and passes the index as a parameter. A list has no GetGoals, and a get method takes no parameter anyway. Pick the element first: self.__Players[Index].
This calls the method on the class, not on an object, so Python does not know which player you mean — TypeError: missing 1 required positional argument: 'self'. Methods are called on objects.

5. For recognition only — what inheritance looks like

Next week is all about inheritance. For now you only need to recognise it, so that you can tell the two apart.

        self.__Genre = Genre             # STRING — the one extra attribute

  • Check, then store, then count. The book goes into element self.__Count — the next free one — and only then does the counter go up. Doing it the other way round leaves element 0 empty and runs off the end one book early.

  • Four separate lines of Added = Fiction.AddBook(...) and a test after each is equally good. The loop over a list of new books is just shorter.

A music app stores playlists. The design says:

Candidate response

What the examiner says

It runs. It still loses most of the declaration marks.

  • ✗ Inherits from Song. A playlist is not a song. Song is in the data type column of an attribute, so this is containment. The class-header mark is lost.
  • ✗ Wrong parameters. The design gives the constructor one parameter, PlaylistName. Title and Artist belong to a song, and are only here because the candidate chose inheritance.
  • ✗ No Songs array. The attribute that holds the songs is missing entirely. Every later part — adding a song, listing the songs, counting them — now has nowhere to work, so the error costs marks well beyond this part.
  • ✓ PlaylistName and SongCount are private, typed, and SongCount is set to the fixed value 0 inside the constructor. Credited.

What would have scored

class Playlist:
    def __init__(self, PlaylistName):
        self.__PlaylistName = PlaylistName    # STRING
        self.__Songs = [None] * 50            # ARRAY[0:49] OF Song
        self.__SongCount = 0                  # INTEGER

The habit to build: before you write the class header, run your finger down the data type column. If the name of another class is there, it is containment — no brackets after the class name, no super(), and that class's parameters stay out of your constructor.

Checkpoint 3

A design reads: "ElectricCar is a subclass of Car. It has one additional attribute, BatteryRange : INTEGER." Which of these follows the design?

The design says "is a subclass of" — that is inheritance, not containment. An electric car does not have a car inside it; it is one. Look for the class name in the data type column first, but read the description too.
Nothing in the design gives Car any new attribute, and an ordinary car does not have electric cars. This invents a relationship that is not there.
Right relationship, wrong direction. The class in brackets is the parent. This makes every ordinary car a kind of electric car.
"Is a subclass of" means inheritance, and the parent goes in the brackets: an electric car is a car, with one extra attribute of its own. Next lesson is about writing its constructor properly.
