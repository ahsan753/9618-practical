How this lesson works

No new content today. This is the dress rehearsal: one Paper 4 question of 32 marks, at exam pace, followed by honest marking and a diagnosis of exactly which lesson to go back to.

  1. Warm up (15 minutes). Do Now, then practise decoding a class design on a small example. Nothing here is timed.
  2. The timed attempt (65 minutes). Start the clock, then write the whole program in your own IDE — IDLE, Thonny or VS Code — as you will in the exam. Paste each part into the Evidence Document as you finish it. No notes, no earlier lessons, no searching.
  3. Mark, diagnose, submit (10 minutes). Self-mark against the mark scheme, find your weakest lesson in the diagnosis table, and submit the Evidence Document on Teams.

Why 65 minutes

Paper 4 is 75 marks in 2 hours 30 minutes — about two minutes per mark. This question is worth 32, so 65 minutes is exam pace. If you cannot do it in one sitting, split it across two home periods: the timed attempt in one, the marking and evidence in the next. Do not split the timed attempt itself.

If the clock runs out, stop writing, note which part you reached in the Evidence Document, and then finish the program untimed. Both numbers are useful — the first tells you about pace, the second about knowledge.

Exam technique

The first five minutes — read the design, not the code you remember

Examiners keep saying the same thing: the strongest candidates are not the ones who know the most syntax. They are the ones who follow the design they are given. "Data structures differ each year to test if candidates can manipulate them when they are working in a slightly different way" (June 2023). So before you type a single line, spend five minutes with a pen.

  1. Read every part first. Later parts tell you what earlier methods are for. Part (i) of today's question explains why part (g) has to return a value rather than output it.
  2. Label each class. Does another class's name appear in its data type column? Then it has those objects — containment, no brackets. Does the description say "subclass of" or "inherits from"? Then it is a — inheritance, brackets and super().__init__.
  3. Label each attribute P (from a parameter) or F (fixed value). Only the P attributes appear in the constructor header. A child constructor takes the parent's P attributes first, then its own.
  4. Label each method R (returns) or O (outputs). For every R, ask: does it return on every path, and where in the program is the value stored and used?
  5. Work out the expected output from the test data before you write any code. Then you will know immediately when the program is wrong.

Checkpoint 1

How many parameters, after self, does the constructor of ExpressParcel take?

The child has to receive the parent's parameters too, so that it can pass them to super().__init__. An express parcel still needs an ID and a weight — it is a parcel.
Two problems. The parent's parameters are missing, and Priority is always 1 — a fixed value, assigned inside the constructor. Taking a fixed value as a parameter is a mark lost in Lesson 1 and again here.
The parent's two P attributes, then the child's one P attribute. Delivered and Priority are fixed values, so neither appears in the header — the parent's constructor sets Delivered, and the child sets Priority to 1 itself.
Right idea for the parent's parameters — but Priority is always 1 when the object is created. It is assigned inside the constructor, not passed in.

Checkpoint 2

Load is declared as ARRAY[0:19] OF Parcel. Which of these can be passed to LoadParcel()?

An ExpressParcel is a Parcel — it has everything a parcel has. Anywhere a Parcel is expected, a child object can go. That is exactly how Lesson 5's extension put a junior member into a club built for members.
An express parcel is a parcel, so it can go anywhere a parcel can. The van can then call GetParcelID() on every element without caring which class each one is — and an overridden method would run in the right version for each. That is polymorphism doing real work.
The design says LoadParcel(NewParcel) — one parameter, and it is a parcel object. The caller creates the object and passes it. Passing the separate values instead was reported by examiners in November 2022 and June 2024.
The array is declared OF Parcel, so ordinary parcels certainly belong in it. Having more attributes does not make a class "more" acceptable — what matters is the is a relationship.

Checkpoint 3

Which version of FindParcel follows the design?

The else returns -1 as soon as the first parcel does not match, so the loop never reaches the second. Not found can only be decided after every stored parcel has been checked.
The return -1 is in the right place, but the loop runs over all twenty elements. Unfilled elements hold None, and None.GetParcelID() crashes whenever the ID is not found and the van is not full. Loop to the counter.
Only the stored parcels are checked, the index is returned the moment the match is found, and -1 is returned only once the loop has finished without one. A return on every path, in the right place.
The design says returns the index. Printing it gives the caller nothing to store — and then the method still returns -1 every time, even when the parcel was found. Outputting where a return is required is reported in nine of the last ten exam series.

Question 1

A city runs a bike hire scheme from several hire stations. A program is to be written using Object-Oriented Programming. There are two kinds of bike: ordinary bikes, and electric bikes, which also have a battery. Each hire station stores up to 10 bikes.

The class Bike stores data about one bike.

Bike
BikeID : STRINGthe bike's unique ID, for example "B101"
Model : STRINGthe model of the bike
HireRate : INTEGERthe cost of hiring the bike for one hour
HoursHired : INTEGERthe total number of hours the bike has been hired for, initialised to 0
Available : BOOLEANTRUE if the bike can be hired, initialised to TRUE
Constructor()takes the bike ID, model and hire rate as parameters, and initialises all the attributes
GetBikeID()returns the bike ID
GetAvailable()returns the value of Available
Hire(Hours)if the bike is available: adds Hours to HoursHired, sets Available to FALSE and returns the cost, Hours multiplied by HireRate.
If the bike is not available, returns -1

The class EBike inherits from Bike.

EBike
BatteryLevel : INTEGERthe percentage of charge in the battery
Constructor()takes the bike ID, model, hire rate and battery level as parameters. Calls the parent constructor and initialises BatteryLevel
Hire(Hours)overrides the parent method.
If BatteryLevel is less than 20, returns -1.
Otherwise calls the parent's Hire() method. If the value it returns is not -1, reduces BatteryLevel by 10 for every hour hired. Returns the value returned by the parent's method.

The class HireStation stores the bikes at one station.

In the exam you would move on, and parts are marked independently — so move on here too. If you open a hint, write "hint used" beside that part in the Evidence Document. Honesty is what makes the diagnosis work.

  • (a) Three P attributes, two F attributes. Only the P ones are in the constructor header.
  • (b) Neither method takes a parameter beyond self.
  • (c) Two paths, two returns. Change the attributes before the return — nothing after a return runs.
  • (d) Four parameters. The next line passes three of them to super().__init__.

Accepted alternatives

  • MP12 and MP15: Bike.__init__(self, BikeID, Model, HireRate) and Bike.Hire(self, Hours).
  • MP14: testing for the battery being 20 or more first, with the -1 in the else.
  • MP24–MP25: a while loop with a found flag, provided the value returned by Hire() is the value returned by HireBike().
  • MP28: creating each bike in a variable first, or a loop over a list of the test data.

Not credited, however good the code looks

  • HoursHired, Available or a fixed value taken as a constructor parameter — MP2 lost, as well as the point for that attribute.
  • print(Hours * self.__HireRate) in place of return — MP9 lost, and everything that relies on the value fails with it.
  • Changing Available after the return line — MP8 lost. That line never runs.
  • super().Hire(Hours) called inside an if condition and again on the next line — MP15 lost. The bike is hired twice: the second call finds it unavailable and returns -1.
  • self.__Available or self.__HireRate anywhere in EBike — MP15 lost. They are private to Bike.
  • class HireStation(Bike): — MP18 lost. Bike is in the data type column: a station has bikes.
  • HireBike() that outputs a message instead of returning — MP24 lost. The design says returns, and part (i) depends on it.
  • Calling HireBike() without storing what it returns, then calling it again to print the cost — MP29 lost, and the second call reports the bike as unavailable.

Python — Paper 4 
# 1(a)
class Bike:
    def __init__(self, BikeID, Model, HireRate):
        self.__BikeID = BikeID       # STRING
        self.__Model = Model         # STRING
        self.__HireRate = HireRate   # INTEGER
        self.__HoursHired = 0        # INTEGER
        self.__Available = True      # BOOLEAN

    # 1(b)
    def GetBikeID(self):
        return self.__BikeID

    def GetAvailable(self):
        return self.__Available

    # 1(c)
    def Hire(self, Hours):
        if self.__Available == True:
            self.__HoursHired = self.__HoursHired + Hours
            self.__Available = False
            return Hours * self.__HireRate
        else:
            return -1


# 1(d) an EBike IS A Bike
class EBike(Bike):
    def __init__(self, BikeID, Model, HireRate, BatteryLevel):
        super().__init__(BikeID, Model, HireRate)
        self.__BatteryLevel = BatteryLevel     # INTEGER

    # 1(e) overrides Bike.Hire
    def Hire(self, Hours):
        if self.__BatteryLevel < 20:
            return -1
        Cost = super().Hire(Hours)             # store what the parent's method returns
        if Cost != -1:
            self.__BatteryLevel = self.__BatteryLevel - 10 * Hours
        return Cost


# 1(f) a HireStation HAS bikes — no brackets
class HireStation:
    def __init__(self, StationName):
        self.__StationName = StationName       # STRING
        self.__Bikes = [None] * 10             # ARRAY[0:9] OF Bike
        self.__NumberOfBikes = 0               # INTEGER

    def AddBike(self, NewBike):
        if self.__NumberOfBikes < 10:
            self.__Bikes[self.__NumberOfBikes] = NewBike
            self.__NumberOfBikes = self.__NumberOfBikes + 1
            return True
        else:
            return False

    # 1(g)
    def HireBike(self, BikeID, Hours):
        for Index in range(0, self.__NumberOfBikes):
            if self.__Bikes[Index].GetBikeID() == BikeID:
                return self.__Bikes[Index].Hire(Hours)
        return -1

    # 1(h)
    def CountAvailable(self):
        Count = 0
        for Index in range(0, self.__NumberOfBikes):
            if self.__Bikes[Index].GetAvailable() == True:
                Count = Count + 1
        return Count


# 1(i) main program
Station = HireStation("Harbour Road")
Added = Station.AddBike(Bike("B101", "City Cruiser", 4))
Added = Station.AddBike(Bike("B102", "Trail Runner", 5))
Added = Station.AddBike(EBike("E201", "Volt 500", 9, 85))
Added = Station.AddBike(EBike("E202", "Volt 500", 9, 15))
Added = Station.AddBike(Bike("B103", "City Cruiser", 4))

Requests = [["B102", 3], ["E201", 2], ["E202", 1], ["B102", 2], ["B777", 1]]
for Request in Requests:
    Cost = Station.HireBike(Request[0], Request[1])
    if Cost == -1:
        print(Request[0] + " cannot be hired")
    else:
        print(Request[0] + " hired for " + str(Request[1]) + " hours, cost " + str(Cost))

print("Bikes available: " + str(Station.CountAvailable()))
  • Polymorphism is doing the work in (g). HireBike calls Hire() on whatever is in the array. For E201 and E202 that is EBike's version, with the battery check; for the others it is Bike's. The station never asks which class a bike is.
  • The value returned travels three levels. Bike.Hire returns the cost to EBike.Hire, which stores it and returns it to HireStation.HireBike, which returns it to the main program, which stores it and tests it. Break any link and the output fails — that chain is exactly what examiners mean by "using what a call returns".
  • (i) uses Added = … even though nothing is tested here. Keeping what a method returns is a habit; in a question that asked for a club-full message, it would be the mark.
