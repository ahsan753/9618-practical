Vocabulary

Key terms — learn these wordings

TermDefinition that earns the mark
Array of objectsAn array whose elements are each an object of the same class. Its data type is that class — ARRAY[0:4] OF Member.
ElementOne position in an array, identified by its index.
IndexThe number that identifies an element's position. In Python the first index is 0.
Linear searchChecks each element in turn, from the first, until the item is found or every element has been checked.
Return valueThe value a function or method passes back to the point where it was called.

What will not earn the mark

"An array of objects is a list of classes" — no mark; the elements are objects (instances), not classes. "A linear search looks through the array" — incomplete; say it checks each element in turn and says when it stops.

PRIMM · Step 3

Investigate — arrays of objects

1. Declaring the array — and showing its type

Shelf = [None] * 3                  # ARRAY[0:2] OF Book
Shelf[0] = Book("Dune", 412)

[None] * 3 makes an array of three empty elements; each one then has a new object stored in it. The comment does the same job as last week's # STRING: Python cannot declare the type, so you show the examiner that this is an array of type Book. Building it with Shelf = [] and Shelf.append(Book(...)) works just as well — keep the comment either way.

2. Array, then element, then method

You writeWhat happens
Shelf[1].GetTitle()✓ Element 1's title is returned.
Shelf.GetTitle()✗ Crash — the list has no such method.
Shelf[3].GetTitle()✗ IndexError — a three-element array ends at index 2.
GetTitle(Shelf[1])✗ Crash — a method is not a free-standing procedure; it is called on an object with a dot.

3. Looping over every element

for Index in range(0, 3):         # pseudocode: FOR Index ← 0 TO 2
    print(Shelf[Index].GetTitle())

The loop variable is the index, so Shelf[Index] is the object for this pass. The end of the range is one greater than the last index. When a question gives you FOR Index ← 0 TO 4, Python needs range(0, 5).

4. Using what comes back — four patterns

Almost every Paper 4 OOP question asks for one of these. Each one calls a get method on every element and does something with the value returned.

PatternThe shape of it
TotalTotal = 0 before the loop; Total = Total + Shelf[Index].GetPages() inside it; use Total after it.
CountCount = 0 before; if Shelf[Index].GetPages() > 400: Count = Count + 1 inside.
Best so farStart with the first object; replace it whenever an element beats it — the Predict program.
SearchCompare each element's value with the target; return Index the moment it matches; return -1 only after the loop.

5. Compare the value, not the object

Shelf[Index] == "Dune" never crashes and is never true: it compares a whole Book object with a string. You want Shelf[Index].GetTitle() == "Dune". Comparing the wrong thing — the index instead of the element, or the whole object instead of one field — is reported in six of the last ten series, and it is nasty because the program runs and simply never finds anything.

Checkpoint 1

Shelf holds three Book objects. Which line outputs the title of the third book?

This calls the method on the whole array and passes the index as a parameter. The list has no GetTitle method, and a get method takes no parameter anyway. Pick the element first: Shelf[2].
The third book is at index 2, because the first is at 0. Shelf[3] is past the end of a three-element array and crashes with an IndexError.
The right element, but it reaches into a private attribute from outside the class. That crashes, and it bypasses the get method the question is testing.
Array, then element, then method — and the returned title goes straight into print.

Checkpoint 2

Inside a loop, which condition is true when the book at Index is called Emma?

This compares a whole Book object with a string. It runs without an error and is never true, so the search silently finds nothing. Compare the value returned by a get method.
No brackets, so the method is never called — this compares the method itself with a string, which is never true. Every method call needs its (), even with no parameters.
The method is called on the element, and the title it returns is compared with the string.
A single = is assignment, not comparison. Python stops with a SyntaxError. Comparison is ==.

Changes to make

  2. Write a function FindBook(SearchTitle) that returns the index of the book with that title, or -1 if it is not on the shelf.
  3. In the main program, output Total pages: 1119 using TotalPages().

Model answer — check yours against this
Python — Paper 4 
def TotalPages():
    Total = 0
    for Index in range(0, 3):
        Total = Total + Shelf[Index].GetPages()
    return Total

def FindBook(SearchTitle):
    for Index in range(0, 3):
        if Shelf[Index].GetTitle() == SearchTitle:
            return Index
    return -1

print("Total pages: " + str(TotalPages()))

Position = FindBook("Holes")
if Position == -1:
    print("Holes is not on the shelf")
else:
    print("Holes is at index " + str(Position))

Position = FindBook("Beloved")
if Position == -1:
    print("Beloved is not on the shelf")
else:
    print("Beloved is at index " + str(Position))
  • The functions go outside the class — they work with books, they are not part of one. They can read Shelf because it is declared in the main program.
  • In FindBook, return -1 is lined up with the for, not the if. It runs only once the loop has checked every book.
  • Position = FindBook(...) calls the search once and keeps the answer. Writing if FindBook("Holes") != -1: and then calling FindBook again inside the if does all the work twice — and when a call changes something, calling it twice is a real bug that examiners report in five series.

The marks

Exam technique — where the lines go matters

With loops and returns, a line of code in the wrong place — inside the loop instead of before or after it — turns a correct idea into a wrong answer that still runs.

Predict, then reveal. The question says: "Write a function AveragePages() that returns the average number of pages of the three books in Shelf." A candidate writes this. It runs, and returns 137.33…. The right answer is 373.0. Find every fault before you open the answer.

Candidate response 
def AveragePages():
    for Index in range(0, 2):
        Total = 0
        Total = Total + Shelf[Index].GetPages()
        return Total / 3
What the examiner says
  • ✗ range(0, 2) misses the last book. It visits indexes 0 and 1 only. Three books need range(0, 3).
  • ✗ Total = 0 is inside the loop. It is reset on every pass, so it can never hold more than one book's pages. Initialise once, before the loop.
  • ✗ return is inside the loop. The function hands back its answer after the first book and stops — the loop never gets a second pass. That is why the answer is 412 ÷ 3.
  • ✓ Shelf[Index].GetPages() — array, element, method, and the returned value is used. That line is credited.
What would have scored 
def AveragePages():
    Total = 0
    for Index in range(0, 3):
        Total = Total + Shelf[Index].GetPages()
    return Total / 3

The habit to build: for every line in a loop question, ask "once, or every time?" Setting up a total happens once — before. Adding to it happens every time — inside. Returning the answer happens once — after. The indentation of that line is your answer to the question.

Checkpoint 3

Using the same three books (Dune, Emma, Holes), what does this function return for FindBook("Holes")?

def FindBook(SearchTitle):
    for Index in range(0, 3):
        if Shelf[Index].GetTitle() == SearchTitle:
            return Index
        else:
            return -1
That is what it should return, but trace it. On the very first pass, Dune is not Holes, so the else runs and the function returns straight away. It never reaches index 2.
On the first pass Dune does not match, the else returns -1, and the function is over. This search can only ever find the first element. The fix: delete the else, and put return -1 after the loop, lined up with for.
A function returns None only when it reaches the end without a return. Here the else guarantees a return on the very first pass.
range(0, 3) only visits 0, 1 and 2, all of which exist — and in fact the loop never gets past index 0.

        NewTotal = self.__Credits + Amount
        if NewTotal > 50:
            NewTotal = 50
        self.__Credits = NewTotal
